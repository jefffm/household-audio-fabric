# Household Audio AirPlay 2 receiver

Pinned source build of Shairport Sync 5.2.1 and NQPTP 1.2.8. The default `receiver` target deliberately is **not** described as containing only those two executables: it also retains the Debian slim base’s shell/core/package utilities and the shared-library dependency closure. Its explicitly requested runtime package set is exactly `libavahi-client3`, `libavcodec59`, `libavformat59`, `libavutil57`, `libconfig9`, `libgcrypt20`, `libplist3`, `libpopt0`, `libsodium23`, `libsoxr0`, `libssl3`, `libswresample4`, and `libuuid1`, installed with `--no-install-recommends` from the pinned snapshot, plus their required transitive dependencies. It excludes D-Bus and Avahi daemons/tools, the FFmpeg/ffprobe CLIs, socat, and capability tools such as setcap. `relay` is a separate, explicitly selected socat image target; `integration-support` contains D-Bus/Avahi test tools and is never a production base.

## Exact runtime model

Run two non-root UID/GID 10001 receiver containers with host networking and one isolated shared IPC namespace. NQPTP exclusively binds UDP 319/320; Shairport listens on TCP 7000. Shairport uses the **host Avahi daemon** by read-only mounting `/run/dbus/system_bus_socket` (usually mount `/run/dbus:/run/dbus:ro`). The host's standard Avahi D-Bus policy must permit method calls to `org.freedesktop.Avahi`; `integration-test.sh` proves this by observing `_airplay._tcp` registration. The receiver image intentionally contains no D-Bus daemon, Avahi daemon/tools, FFmpeg CLI, socat, or capability tooling.

Both processes require realtime scheduling. Grant effective `SYS_NICE` and `rtprio >= 5`; NQPTP runs its main thread `SCHED_FIFO/5`, while Shairport creates FIFO/2-3 audio threads. NQPTP additionally needs effective `NET_BIND_SERVICE`. Entrypoint preflight fails closed when capabilities/limits/D-Bus/identity are absent. The shipped binaries have no file capabilities.

Example policy (translate to the deployment runtime; Docker does not propagate added capabilities to a preselected non-root user):

```text
runAsNonRoot: true; runAsUser/runAsGroup: 10001
allowPrivilegeEscalation: false; readOnlyRootFilesystem: true
capabilities.drop: [ALL]
NQPTP capabilities.add: [NET_BIND_SERVICE, SYS_NICE]
Shairport capabilities.add: [SYS_NICE]
rtprio hard/soft limit: 5
hostNetwork: true; isolated shared pod IPC; /run/airplay tmpfs; host /run/dbus read-only
```

Use seccomp/AppArmor and same-LAN network isolation. Do not expose the receiver beyond the trusted audio LAN.

## Stable identity and pairing boundary

`AIRPLAY_INTERFACE`, `AIRPLAY_ALLOWED_IPV4_CIDR`, and `AIRPLAY_ALLOWED_IPV6_CIDR` are mandatory and must match a host-firewall attestation generated by `install-firewall.sh`; Shairport registers only on that interface. `AIRPLAY_DEVICE_ID` is mandatory and must be exactly 12 hexadecimal digits (six bytes). Inject a stable value from a SOPS-managed Secret/config; never derive it from an ephemeral interface. It becomes `general.airplay_device_id`, providing a stable advertised identity and deterministic upstream accessory key. No password is configured initially.

Do not claim durable Home authorization: in upstream 5.2.1 controller pairings and HomeKit access-control are RAM-only and verification is intentionally transient/permissive. Apple Home registration is optional experimental/best-effort, not a release gate. Same-LAN isolation is the initial security boundary. Current-iPhone Control Center discovery, playback, restart, and reconnect are physical release gates.

## Audio and metadata contracts

Stdout is exclusively raw headerless PCM: `48000 Hz`, `S32_LE`, stereo. Never merge stderr into stdout. Software volume is ignored (`ignore_volume_control=yes`). Session and volume metadata use `/run/airplay/metadata`, a mode-0600 FIFO on the `/run/airplay` tmpfs; cover art is disabled. The upstream raw metadata stream emits volume (`pvol`) events, but synthesizing an authenticated AirPlay 2 volume event without a controller is not a truthful unit test, so that event is a physical integration gate.


## Host boundary contract (production deployment remains gated)

`compose.integration-test-only.yaml` is explicitly integration-test-only and uses the test-capability derivative. It is not a runnable or validated production example. Production remains gated on CRI validation that `runAsNonRoot` processes receive effective narrow capabilities without file caps or privilege escalation. The production image intentionally fails closed under ordinary Docker controls. Before starting it, install or verify the host rule (as root, without granting `NET_ADMIN` to either receiver):

```sh
AIRPLAY_INTERFACE=audio0 AIRPLAY_ALLOWED_IPV4_CIDR=192.0.2.0/24 \
  AIRPLAY_ALLOWED_IPV6_CIDR=fe80::/10 AIRPLAY_BOUNDARY_ATTESTATION=/etc/household-audio-airplay/verified \
  ./install-firewall.sh apply
```

The nftables table accepts TCP 7000 and UDP 319/320 for IPv4 and IPv6 only when ingress interface and the corresponding allowed-network CIDR match, and rejects those ports on Tailscale, the default interface, and every other interface. The read-only attestation is mounted into both containers; preflight fails if its declared interface/IPv4/IPv6 CIDRs or canonical ruleset hash differs or the interface does not exist. `install-firewall.sh verify` re-reads the active rules before refreshing the attestation. Later GitOps may install this host rule, but receivers never receive `NET_ADMIN`.

## Build and tests

```sh
docker build --target receiver -t household-audio-airplay:test -f Containerfile .
./test.sh
IMAGE=household-audio-airplay:test ./test.sh
IMAGE=household-audio-airplay:test ./integration-test.sh
FORCE_TEMP_AVAHI=1 IMAGE=household-audio-airplay:test ./integration-test.sh  # exercise fallback

docker build --target relay -t household-audio-relay:test -f Containerfile .
```

The integration test uses host Avahi when available, otherwise launches temporary D-Bus+Avahi. It verifies live FIFO NQPTP, shared memory, Shairport TCP 7000, modern `_airplay._tcp` discovery, clean idle PCM stdout, and the metadata FIFO. A test-only file-capability derivative works around Docker's non-root capability behavior; production must use CRI-granted effective capabilities.

Role-specific `healthcheck.sh` checks NQPTP bound ports/main-thread FIFO/shared timing memory and Shairport process prerequisites/TCP listener/D-Bus/metadata FIFO. It does not claim Shairport stream-thread FIFO or working PCM before a physical stream. Relay health treats a blocked process as healthy because socat is applying downstream TCP backpressure.

## Compliance and reproducibility

The base digest, immutable Debian snapshot, upstream versions, and source hashes are pinned in `SOURCES.lock`. Exact upstream license/notices are copied from each source tree. `generate-package-inventory.sh` runs inside the final architecture build and creates a package inventory (not a complete file-level final-image SBOM) that records the base digest, every installed Debian package/version/architecture, upstream binaries, and binary hashes in SPDX 2.3 tag/value format. The runtime includes GPL-covered FFmpeg libraries; distributors must preserve notices and satisfy the corresponding GPL/LGPL source obligations (including an appropriate source offer), not rely solely on the OCI label.
